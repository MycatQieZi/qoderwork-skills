# Token Cost Estimator（Token 成本预评估）

在正式回答或执行**之前**，先花极少的篇幅对当前请求做一次 **token 成本预评估**，用四个量级档位衡量预计消耗。核心目的：**在大型、笼统、边界不清的问题上，先对齐成本与范围，再动手**，避免一头扎进耗费巨大、方向可能跑偏的任务。

> 本技能是**通用模板**：不依赖任何特定 Agent 的私有记忆，也不做精确计费；只做「量级判断 + 是否需要先确认」，任何工具/协作者都可复用。

## 触发时机

在**接手一个新请求、尚未开始实际工作时**先做评估，尤其命中以下特征之一：

- **笼统/宽泛**：目标模糊、没有明确交付物，如「帮我优化一下这个项目」「分析下这些数据」。
- **大型/多步**：涉及多文件、多模块、多阶段，或需要大量读取/生成。
- **边界不清**：范围可大可小，用户没有划定终点。
- **开放式产出**：可能产生长文档、全量重构、大范围检索等。

> 对于**明确、小范围、单步**的请求（如「改这一行」「解释这个函数」），可跳过评估直接执行，不必增加噪音。

## 评估维度

从四个维度快速估量级，不做精算：

| 维度 | 关注点 |
|------|--------|
| **输入体量 Input** | 需读取的文件/代码/资料规模 |
| **输出体量 Output** | 预计生成的代码/文档/回答长度 |
| **步骤深度 Steps** | 需要的工具调用轮次、迭代次数 |
| **不确定性 Uncertainty** | 范围是否清晰、是否可能反复返工 |

## 量级档位

综合四个维度，给出**单一档位**（就高不就低，任一维度显著偏大即抬档）：

| 档位 | 大致特征 | 默认动作 |
|------|----------|----------|
| **低** | 单文件/单步、产出简短、范围清晰 | 直接继续，无需提示 |
| **中** | 少量文件/几步迭代、产出中等 | 可直接继续，必要时一行提示 |
| **高** | 多文件/多步、产出较长、范围偏大 | **先提示 + 收窄建议，请用户确认后再继续** |
| **超高** | 全项目级/大范围检索/长文档/高返工风险 | **先提示 + 收窄建议，请用户确认后再继续** |

## 动作规则：高成本需确认

- **低 / 中**：正常继续执行，不打断（中档可在一行内附带成本提示）。
- **高 / 超高**：**先输出成本提示与收窄建议，然后停下来等待用户确认，不擅自开工**。用户确认（或明确要求全量做）后再继续；判断权始终交还用户。

## 输出格式

### 高 / 超高档（需确认）

```
> 💰 成本预评估：{档位}。预计 {简述主要成本来源，如"需读取多模块 + 生成长文档"}。
> 收窄建议：{1–3 条可降低成本的做法，如"先聚焦某模块 / 先出大纲再展开 / 限定范围到 X"}。
> 需要我按{哪种方式}继续，还是先按你的收窄意见调整？
```

示例：

```
> 💰 成本预评估：超高。预计需通读整个仓库并产出重构方案 + 全量改动，输入与输出体量都很大。
> 收窄建议：① 先只梳理目录与模块边界出一份地图；② 或先聚焦一个最痛的模块试点；③ 明确本轮交付物与终点。
> 需要我按「全量重构」继续，还是先从某个模块试点？
```

### 中档（可选一行提示）

```
> 💰 成本预评估：中。范围可控，我直接开始，如需缩小范围可随时打断。
```

### 低档

不输出提示，直接执行。

## 原则

- **先估后做**：动手前先判断量级，尤其对笼统/大型问题。
- **就高不就低**：拿不准时抬档，宁可先确认。
- **只提量级**：给档位与成本来源，不做精确 token 计费，避免过度精算。
- **不阻断低成本**：小任务直接做，别为提示而提示。
- **高成本必确认**：高/超高档先提示 + 收窄建议并等待确认，把范围决定权交还用户。
- **收窄可执行**：每条收窄建议都应是能立刻采纳、切实降低成本的做法。
