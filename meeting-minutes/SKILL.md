# Meeting Minutes（会议纪要管理）

将原始会议记录或逐节内容转化为**标准化的 HTML 会议纪要报告**。核心思路：先确认结构 → 再收集内容 → 最后生成报告。

> 本技能是**通用模板**：章节定义见 [template.md](template.md)，HTML 骨架见 [report-template.html](report-template.html)。报告为纯 HTML，无外部依赖，任何浏览器均可打开。

## 触发时机

- 用户需要"整理会议纪要""生成会议报告""写一份会议记录"
- 用户提供了一份或多份原始会议记录需要结构化
- 用户提到"会议纪要模板""meeting minutes"

## 标准化模板结构

共 9 个章节，详见 [template.md](template.md)：

| 章节 | 内容 | 必填 |
|------|------|------|
| 1. 会议主题 | 一句话概括核心议题 | ✅ |
| 2. 基本信息 | 时间、地点、主持人、记录人 | ✅ |
| 3. 参会人员 | 姓名与角色/部门 | ✅ |
| 4. 讨论议题 | 议题名称 + 讨论摘要 + 各方观点 | ✅ |
| 5. 已解决问题 | 已达成共识的结论与决策依据 | 选填 |
| 6. 待解决问题 | 遗留问题、阻塞原因、后续安排 | 选填 |
| 7. 行动计划 | 行动项、负责人、截止日期 | 选填 |
| 8. 下次会议 | 暂定时间与预计议题 | 选填 |
| 9. 备注/附件 | 补充说明与参考资料 | 选填 |

## 工作流程

### 阶段 1：展示提纲并确认

```
提纲确认清单：
- [ ] 1. 读取 template.md，向用户展示 9 个章节的提纲结构
- [ ] 2. 询问用户是否需要增删或调整章节
- [ ] 3. 根据用户反馈调整模板结构
- [ ] 4. 确认最终提纲后，进入内容收集阶段
```

展示提纲时使用简洁的章节列表，让用户一眼看清结构。用户可要求删除章节、添加自定义章节、调整顺序。

用户确认后，记录**最终章节清单**，后续收集与生成均以此为准。

### 阶段 2：内容收集 —— 双模式

向用户说明两种模式，让其选择：

| 模式 | 适用场景 | 用户操作 |
|------|----------|----------|
| **A. 分段提供** | 用户有各章节独立内容，或希望逐节精细控制 | 按章节逐一提供 `.md` 文件或直接粘贴内容 |
| **B. 完整上传** | 用户已有一份完整的原始会议记录 | 上传/粘贴完整文件，skill 自动提取各章节内容 |

#### 模式 A：分段提供

```
分段收集清单：
- [ ] 1. 按最终章节清单，逐节向用户索要内容
- [ ] 2. 用户可提供 .md 文件路径，或直接粘贴内容
- [ ] 3. 每收到一节内容，复述确认关键信息
- [ ] 4. 全部收集完成后，进入阶段 3（生成报告）
```

- **逐节交互**：提示用户提供第 N 节内容，如"请提供「会议主题」的内容（.md 文件路径或直接粘贴）"。
- **即时确认**：每节收到后简短复述关键信息（如"收到：会议主题为「2025-Q3 产品路线图规划会」"），发现明显缺失即时追问。
- **允许跳过**：选填章节可跳过，用户回复"跳过"或"无"即可。

#### 模式 B：完整上传

```
自动提取清单：
- [ ] 1. 接收用户上传/粘贴的完整会议纪要文件
- [ ] 2. 通读全文，按最终章节清单逐一提取对应内容
- [ ] 3. 将提取结果按章节整理为结构化摘要，向用户展示
- [ ] 4. 用户确认或修正各节内容后，进入阶段 3（生成报告）
```

提取策略：

- **会议主题**：从标题、首段或"主题/议题"关键词附近提取。
- **基本信息**：识别日期时间格式（`YYYY-MM-DD HH:MM`）、地点、人名+主持/记录关键词。
- **参会人员**：识别"参会/出席/与会"块中的人名列表。
- **讨论议题**：按编号或分段标题识别各议题，提取对应的讨论要点与观点。
- **已解决问题**：识别"结论/决议/达成共识/确定"等关键词引导的内容。
- **待解决问题**：识别"待定/遗留/待跟进/TODO/未决"等关键词引导的内容。
- **行动计划**：识别含有人名+日期+任务描述的行或表格行。
- **下次会议**：识别"下次/下回/next meeting"关键词附近的时间与议题。
- **备注**：识别"备注/附件/参考/附录"关键词下的内容。

> 提取结果必须向用户展示并等待确认。对不确定的条目标注 `⚠️ 待确认`，由用户修正。

---

### 阶段 3：生成 HTML 报告

```
生成清单：
- [ ] 1. 按最终确认的章节清单与内容，生成完整 HTML 文件
- [ ] 2. 写入项目根目录，文件名格式：meeting-minutes-{YYYY-MM-DD}-{主题简写}.html
- [ ] 3. 向用户报告文件路径，并简要复述报告关键信息
```

#### HTML 报告要求

- **独立可打开**：所有 CSS 内联于 `<style>` 标签，无外部依赖。
- **打印友好**：使用 `@media print` 优化打印样式。
- **中文优化**：使用系统默认中文字体栈，排版清晰。
- **结构分明**：章节标题层级清晰，表格规整，关键信息突出。

生成时读取 `report-template.html`，按最终确认的章节清单把内容填进骨架（骨架里的 HTML 注释已标明各节位置）。

## 原则

- **先确认再收集**：提纲未确认前不索要内容，避免返工。
- **内容不臆测**：提取不确定的条目标注"待确认"，不替用户编造。
- **结构优先于修饰**：HTML 以信息清晰为首要目标，不过度设计。
- **用户主导**：确认权始终交还用户——提纲确认、内容确认、最终报告确认。
- **选填不强制**：选填章节允许为空，不反复追问。
- **文件名可追溯**：报告文件名含日期与主题，便于归档查找。
