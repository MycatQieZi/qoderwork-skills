# Scope Anchor（领域与目标锚点）

为项目/功能**预先锚定**三件事——**领域、作用对象、基础目标**——并落地为项目根目录下的 `SCOPE.md`。此后无论项目初始化、还是提问答疑，都以该文件为**权威范围来源（single source of truth）**，避免范围漂移、答非所问、越做越偏。

> 本技能是**通用模板**：不依赖任何特定 Agent 的私有记忆，锚点仅存于项目内的纯文本 `SCOPE.md`，任何工具/协作者都可读取与版本化。

## 核心概念

| 字段 | 含义 | 示例 |
|------|------|------|
| **领域 Domain** | 项目所属的问题域/行业/技术域 | 「个人财务记账」「金融法规检索」 |
| **作用对象 Target** | 服务的主体/数据/系统对象 | 「个人用户的收支流水」「中国境内持牌金融机构」 |
| **基础目标 Base Goals** | 必须达成、不可动摇的核心目标（1–5 条） | 「准确归类每一笔支出」 |
| **非目标 Non-Goals** | 明确**不做**的事，划出边界 | 「不做投资建议」「不接入实时行情」 |

`领域 + 作用对象` 决定「做什么、为谁做」；`基础目标 + 非目标` 决定「达到什么、到哪为止」。四者共同构成范围锚点。

## 触发时机

1. **项目初始化**：新项目/新功能开始时，引导用户定义并写入 `SCOPE.md`。
2. **提问答疑**：回答项目相关问题前，先读取 `SCOPE.md`，用其锚定上下文与作答边界。

> 补充：在动手改代码前也可顺带对照锚点确认方向，但这不是本技能的强制环节。

## 工作流程

### A. 项目初始化 —— 建立锚点

```
初始化清单：
- [ ] 1. 检查项目根目录是否已存在 SCOPE.md
- [ ] 2. 若不存在：与用户澄清 领域 / 作用对象 / 基础目标 / 非目标
- [ ] 3. 按模板生成 SCOPE.md（见下方模板）
- [ ] 4. 向用户复述锚点，确认无误
```

- 若信息不足以填满四个字段，**主动提问补齐**，不要臆测。
- 基础目标控制在 1–5 条，每条可验证、可判断达成与否。
- 模板见 [scope-template.md](scope-template.md)，可直接复制到项目根目录改名为 `SCOPE.md`。

### B. 提问答疑 —— 对齐锚点

```
答疑清单：
- [ ] 1. 读取项目根目录 SCOPE.md（不存在则提示可先用本技能初始化）
- [ ] 2. 判断当前问题/需求是否落在 领域 + 作用对象 + 基础目标 内
- [ ] 3a. 在范围内：正常作答，回答服务于基础目标
- [ ] 3b. 偏离范围：先给出「范围提示」，再继续作答（不阻断）
```

## 偏离处理：仅提示、不阻断

一旦判断当前请求偏离已预设的领域/作用对象/基础目标（或落入非目标），**先输出一条简短的范围提示，然后照常继续执行用户请求**。判断权交还用户，不擅自中止或拒绝。

提示格式（一行引用块，简明扼要）：

```
> ⚠️ 范围提示：当前请求偏离预设锚点——{偏离点}（当前领域：{领域}｜基础目标：{相关目标}）。如需扩展范围，可更新 SCOPE.md。
```

示例：

```
> ⚠️ 范围提示：当前请求偏离预设锚点——「接入实时股票行情」属于已声明的非目标（当前领域：个人财务记账｜作用对象：个人收支流水）。如需扩展范围，可更新 SCOPE.md。

不过我可以先按你的要求实现……
```

- 每次回复中同一偏离**最多提示一次**，避免打断节奏。
- 提示只陈述事实与边界，不做说教。
- 用户明确要求扩展范围时，引导其更新 `SCOPE.md`，使锚点与现实保持一致。

## 原则

- **锚点唯一**：`SCOPE.md` 是范围的权威来源；有歧义时以它为准。
- **可移植**：纯文本、无工具耦合，任何 Agent/协作者皆可读取与版本化。
- **不阻断**：偏离时提示而非拦截，尊重用户最终判断。
- **锚点鲜活**：范围随需求演进时，及时更新 `SCOPE.md`，而非放任漂移。
- **简洁**：提示一行即可，不喧宾夺主。
