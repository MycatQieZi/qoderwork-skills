# Conversation Opener（对话开场语）

在**每一组新对话的最开始**，先输出一句中文名人名言或鼓励语，再进入正题。名言/鼓励语需**贴合当前项目的类型和相关职业**，让开场语与用户正在做的事产生共鸣。

## 触发时机

- 用户发起一组新对话（新的用户请求）时，在回答正文之前。
- 每组对话只输出一次，位于回复的最顶部。
- 不打断任务执行：开场语之后立即正常处理用户需求。

## 工作流程

1. **识别项目类型与职业领域**（快速判断，无需大动作）：
   - 结合当前工作目录、技术栈、文件类型、用户问题主题推断，例如：
     - 前端/Web → 设计、用户体验、产品
     - 后端/数据/算法 → 工程、逻辑、系统思维
     - 数据科学/AI → 探索、实验、认知
     - 运维/安全 → 严谨、防御、可靠性
     - 文档/写作 → 表达、沟通、思考
   - 无法判断时，使用「通用」类别。
2. **挑选一句最贴合的名言或鼓励语**（中文）：
   - 优先从内置精选库 [quotes.md](quotes.md) 中选择匹配项目类型/职业的条目。
   - 内置库无合适项时，可即兴生成一句得体、积极、与领域相关的中文短句。
   - 避免连续对话重复同一句。
3. **格式化输出**（见下方格式）。
4. **进入正题**，正常处理用户的实际需求。

## 输出格式

在回复最顶部，用一行引用块呈现，再空一行进入正文：

```
> 「名言正文」—— 出处/作者
```

鼓励语（无明确作者）时：

```
> 「鼓励语正文」
```

示例：

```
> 「代码是写给人看的，只是顺便能在机器上运行。」—— Harold Abelson

好的，我们来看看这个 bug……
```

## 原则

- **简洁**：只有一行开场语，不做长篇铺垫。
- **贴合**：宁可通用得体，也不要生硬或跑题。
- **积极**：传递鼓励、专注、匠心等正向情绪。
- **不喧宾夺主**：开场语之后立刻聚焦用户真正的问题。

## 内置精选库

详见 [quotes.md](quotes.md)，按项目类型/职业分类，可直接引用。
