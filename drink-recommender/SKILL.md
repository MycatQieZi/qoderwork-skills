# Drink Recommender（关键词 + 地址 咖啡/奶茶推荐）

在**从用户对话或当前任务中提取到关键词之后**，根据这些关键词所体现的**情绪、场景与强度**，并**结合用户当前地址**，推荐**附近某家真实咖啡店里的具体一杯**咖啡或奶茶，附**一句**简短理由，帮助用户放松、调节工作节奏。

## 触发时机

- 已经完成关键词提取（无论是本 skill 自行提取，还是流程上游已给出关键词）之后。
- 用户明确请求「推荐一杯喝的 / 来杯咖啡或奶茶」时。
- 每次推荐只给**一杯**，不喧宾夺主，附在回复末尾或独立成段。
- 若当前对话已经推荐过且场景未变，则不重复推荐。

## 工作流程

1. **确认/提取关键词**：
   - 若上游已提供关键词，直接使用。
   - 否则从用户当前问题与任务上下文中提取 1~3 个核心关键词（主题、情绪、时间、强度）。
2. **判断情绪与场景**（快速判断，无需大动作）：
   - 关键词映射到下方「场景 → 饮品」对照表中的某一类，得到目标**饮品类型**（如冰美式、拿铁、奶茶）。
   - 综合考虑：任务强度（高压/轻松）、时间（清晨/深夜/午后）、情绪（疲惫/兴奋/焦虑/庆祝）。
3. **获取当前地址**（按优先级）：
   - 用户在本轮对话中明确给出的地址/位置，直接使用。
   - 本次会话早前已提供且未变更的地址，可复用。
   - 都没有时，**用一句话向用户询问**当前所在位置（城市 + 商圈/街道即可，不索取精确门牌等隐私信息）。
4. **检索附近咖啡店**：
   - 用网络搜索（WebSearch）查询「地址 + 附近咖啡店/咖啡馆」，获取 2~3 家真实存在的店（连锁如瑞幸、星巴克、Manner、库迪，或本地独立咖啡馆均可）。
   - 结合第 2 步的饮品类型，匹配该店菜单中的**具体一款**在售饮品（如瑞幸「生椰拿铁」、Manner「燕麦澳白」、星巴克「馥芮白」）；不确定菜单时，选择该品牌广为人知的招牌款。
5. **挑选一杯最贴合的饮品**：
   - 最终推荐 = **一家店 + 该店的一杯具体饮品**，与关键词场景呼应。
   - 避免连续对话重复同一家店或同一杯。
6. **格式化输出**（见下方格式），附店名、大致位置和一句简短理由。
7. 推荐之后不打断正题，继续正常处理用户的实际需求。

### 降级策略

- 用户不愿提供地址、地址无法确认，或网络搜索不可用/无结果时，**退回通用模式**：只按「场景 → 饮品」对照表推荐一杯饮品类型，不带店铺信息。
- 搜索结果无法确认店铺真实在营业时，注明「以实际营业情况为准」。

## 输出格式

结合地址推荐时，用一行引用块呈现「店 + 具体饮品 + 位置 + 理由」：

```
> ☕/🧋 推荐一杯：「店名 · 饮品名」（大致位置/距离）——一句贴合关键词的理由。
```

示例：

```
> ☕ 推荐一杯：「Manner · 燕麦澳白」（公司楼下步行 5 分钟）——关键词里全是「上线、赶工、深夜」，一杯扎实的澳白帮你稳住清醒。
```

```
> 🧋 推荐一杯：「霸王茶姬 · 伯牙绝弦」（XX 商圈店）——「重构完成、松了口气」，茶香清爽正好犒劳自己。
```

降级为通用模式时：

```
> ☕ 推荐一杯：「冰美式」——关键词里全是「上线、赶工、深夜」，来点纯粹的清醒感。
```

## 原则

- **简洁**：只有一行推荐，附一句理由，不做长篇铺垫。
- **贴合**：饮品要与提取到的关键词情绪/场景呼应，宁可常见得体，也不生硬跑题。
- **真实**：店铺与饮品来自网络检索到的真实信息，不编造不存在的店；不确定时选知名连锁招牌款并注明以实际为准。
- **尊重隐私**：地址只需城市 + 商圈/街道粒度，仅在本次推荐中使用，不主动索取精确住址。
- **一次一杯**：不给一长串选项，直接推荐最贴合的那一杯（一家店 + 一款饮品）。
- **不喧宾夺主**：推荐之后立刻回到用户真正的问题。
